## 二、P0 崩溃级（必修）

### #1 XPC 调用存在双 resume 崩溃路径 + 无超时
- **位置**：`App/XPCHelperClient/XPCHelperClient.swift:54-156`（六个方法同构）
- **问题**：`getProxyWithError` 的 errorHandler 可能 resume 一次，之后 `proxy.xxx { }` 回调若也触发会再次 resume → `CheckedContinuation` 双 resume 必崩。且 Helper 进程挂起（非断连）时 continuation 永久悬挂，调用方 await 卡死；interruption 时旧 connection 未显式 `invalidate()`。
- **修复**：封装统一的 `withXPCContinuation` 辅助函数——内部加 resume 守卫（`NSLock` + flag）、超时兜底（如 3s 返回默认值）、interruption handler 中 invalidate 旧连接。
- **来源**：WorkBuddy（质量高 + 内存中合并）

### #2 NowPlaying 流读取 continuation 泄漏
- **位置**：`App/MediaControllers/NowPlayingController.swift:219-228`
- **问题**：`readData()` 挂起期间若 `close()`（232 行置 nil handler）或任务被取消，continuation 永不 resume → Task 永久泄漏。
- **修复**：用 `withTaskCancellationHandler` 包裹，cancel/close 路径上 resume 一个空 Data 或 throw CancellationError。
- **来源**：WorkBuddy

## 三、P1 高危

### #3 Shelf 持久化：编码在主线程，防抖形同虚设
- **位置**：`App/components/Shelf/Services/ShelfPersistenceService.swift:75-84`
- **问题**：`items` 每次 didSet 都立即在**主线程**做全量 JSON 编码（含 prettyPrinted + 书签 Data），防抖只延迟了写盘。批量拖拽导入时连续触发卡顿。
- **修复**：把 encode 移入 detached task 的防抖窗口内（先 sleep 800ms，未取消再 encode+write）。
- **来源**：WorkBuddy

### #4 ShelfItem 计算属性主线程做书签解析 + 磁盘 I/O
- **位置**：`App/components/Shelf/Models/ShelfItem.swift:65-143,194-206`
- **问题**：`displayName` 执行 `Data(contentsOf:)`、`icon` 调 `NSWorkspace.icon(forFile:)`、`identityKey` 每次 `resolve()` 书签；`ShelfStateViewModel.add()`（ShelfStateViewModel.swift:130）对全部已存条目 map 一遍 → O(n) 次主线程书签解析。
- **修复**：解析结果一次性缓存（存入 item 或旁路字典），`add()` 去重改用预存 key。
- **来源**：WorkBuddy

### #5 剪贴板图片捕获/入库全在主线程
- **位置**：`ClipboardMonitor.swift:104-108`、`ClipboardHistoryStore.swift:57-79,208-215`
- **问题**：TIFF→PNG 转换、SHA256 哈希、blob 写盘、items.json encode+atomic write 均在 `@MainActor`。截全屏大图单次可卡主线程数十至上百 ms。
- **修复**：extract/hash/write 移到后台，仅状态更新回主线程。
- **来源**：WorkBuddy

### #6 剪贴板图片行全尺寸解码（内存峰值）
- **位置**：`App/components/Clipboard/Views/ClipboardItemView.swift:95`
- **问题**：展示尺寸仅 28×28，却 `NSImage(contentsOf:)` 整张 PNG（上限 10MB/条，截图解码后数十 MB 位图）；LazyVStack 滚动时 @State 销毁重建，反复全尺寸解码。
- **修复**：用 `CGImageSourceCreateThumbnailAtIndex`（ImageIO 下采样）生成小图。
- **来源**：WorkBuddy

### #7 置顶剪贴板条目无上限 + RTF/HTML 常驻内存
- **位置**：`App/components/Clipboard/Services/ClipboardHistoryStore.swift:103-124`
- **问题**：`prune()` 中 pinned 条目永不淘汰；`rtfData/htmlData`（各可达 10MB）以 base64 内联存 items.json 并常驻 `items` 数组 → 内存与磁盘均无界增长。
- **修复**：置顶数量设上限；RTF/HTML 也落盘为 blob 只存文件名。
- **来源**：WorkBuddy
- **备注**：Gemini 报告误把 blob 机制评价为"保证物理 RAM 极小"——只对图片成立，富文本不成立。

### #8 持久化静默失败（数据丢失无日志）
- **位置**：`ShelfPersistenceService.swift:77-82`、`ClipboardHistoryStore.swift:35-40,218-220`
- **问题**：编码/写盘失败被 `try?` 吞掉，无任何日志，用户数据静默丢失。
- **修复**：至少 NSLog/os_log；关键路径考虑错误上报或用户提示。
- **来源**：WorkBuddy

### #9 悬浮巢孵化依赖硬编码延时（时序竞态）
- **位置**：`App/components/Shelf/FloatingNestManager.swift:112-119`
- **问题**：`Task.sleep(350ms)` 后再看 `isLoading` 决定是否补睡 300ms——负载高时 load 未完，窗口尺寸算错或触发误判回滚（panel.hide + 清位置记忆）。
- **修复**：把 `ShelfStateViewModel.load` 改为可 await 的异步函数或加完成回调，真正完成后再调整尺寸。
- **来源**：Gemini（WorkBuddy 漏报，已核实属实）

## 四、P2 中危

### #10 Observer token 被丢弃，无法注销
- **位置**：`App/DropNestApp.swift:337-381`（6 个闭包式 addObserver 未存返回值）；`windowScreenDidChangeObserver`（282 行）多屏模式下互相覆盖，`cleanupWindows` 不移除。
- **修复**：统一存 `[Any]` 并在清理时移除。
- **来源**：WorkBuddy

### #11 分享 picker 取消边界泄漏
- **位置**：`App/models/SharingStateManager.swift:52-68,127-138`
- **问题**：picker 弹出后未回调 `didChoose`（点外部 dismiss）时，`activeDelegates`/`activeSessions` 永不回收，`preventNotchClose` 永久卡 true。
- **修复**：对 picker 生命周期加超时兜底或监听 dismiss。
- **来源**：WorkBuddy

### #12 缩略图 cacheKeys 只增不减 + cost 单位错误
- **位置**：`App/components/Shelf/Services/ThumbnailService.swift:23,43-45`
- **问题**：NSCache 自动淘汰不回调，`cacheKeys` 永久残留（文件每改一次产生新 key）；cost 用点尺寸非像素，256MB 上限被低估 2-4 倍。
- **修复**：cost 改用 `width*height*4`；定期清理失效 key。
- **来源**：WorkBuddy

### #13 图片处理全尺寸峰值
- **位置**：`App/components/Shelf/Services/ImageProcessingService.swift:60,87,248`
- **问题**：原图全量解码 + `tiffRepresentation`，`createPDF` 循环同时持有多张全尺寸图，瞬时内存可达数百 MB。
- **修复**：ImageIO 流式/缩略图处理，循环内 autoreleasepool。
- **来源**：WorkBuddy

### #14 拖拽事件每帧一次无意义 MainActor hop
- **位置**：`DropNestApp.swift:208-212`（`Task { @MainActor in ShakeGestureDetector.shared.feed(point) }`）
- **问题**：全局 monitor 本就在主线程触发，60-120Hz 下每事件多一次 Task 分配+调度。
- **修复**：**直接同步调用**（global monitor 已在主线程）。⚠️ 不要按 Gemini 建议做"节流到 30Hz"——会降低摇晃检测的振幅采样精度。
- **来源**：WorkBuddy + Gemini 合并（Gemini 找对位置、开错药方）

### #15 音量键每次拷贝整个 NSGlobalDomain
- **位置**：`App/observers/MediaKeyInterceptor.swift:206`
- **问题**：`playFeedbackSound` 每次按键 `UserDefaults.persistentDomain(forName: "NSGlobalDomain")` 拷贝整个全局域字典。
- **修复**：启动时读一次缓存，或 `CFPreferencesCopyAppValue` 单键读取。
- **来源**：WorkBuddy

### #16 NowPlaying 高频小对象分配
- **位置**：`App/MediaControllers/NowPlayingController.swift:124,212,115-118`
- **问题**：每条 JSON 行新建 `ISO8601DateFormatter()`/`JSONDecoder()`；非 diff 帧 artwork base64 全量解码。
- **修复**：复用 formatter/decoder 实例。
- **来源**：WorkBuddy

### #17 启动时重度串行初始化
- **位置**：`App/DropNestApp.swift:413-431`
- **问题**：启动即初始化 ClipboardMonitor、Battery、Volume、Brightness、KeyboardBacklight（后两者立即唤醒 XPC helper 并发 IPC）；ContentView 的 musicManager 拉起 perl 常驻进程；`ClipboardHistoryStore.init` 主线程 load+prune（Gemini 也指出了容错 JSON 解析阻塞启动）。
- **修复**：HUD 相关 manager 延迟到首次按键/首次开刘海；启动数据反序列化移后台。
- **来源**：WorkBuddy + Gemini 合并

### #18 根视图订阅过多高频源
- **位置**：`App/ContentView.swift:17-19`、`NotchViewCoordinator.swift:85-121`
- **问题**：根 ContentView 同时订阅 coordinator/musicManager/batteryModel；`sneakPeek` 每次音量/亮度键整 struct 发布，触发整棵 NotchLayout body 重估。
- **修复**：HUD 状态下沉到独立子视图订阅。
- **来源**：WorkBuddy

### #19 安全作用域资源泄漏
- **位置**：`App/components/Shelf/ViewModels/ShelfItemViewModel.swift:553`（`copiedURLs` startAccessing 后仅下次复制时 stop，App 退出前不释放）；NestGroupCardView/ShelfItemView 拖拽路径同样缺 deinit 兜底。
- **修复**：deinit/应用退出钩子统一 stopAccessing。
- **来源**：WorkBuddy

### #20 非隔离可变静态状态（data race 风险）
- **位置**：`App/models/NotchViewModel.swift:31,85`（`static var clipboardRowCount`，注释自称 "Non-isolated storage"）
- **问题**：@MainActor 的 ClipboardHistoryStore didSet 写入，严格并发下存在 data race。
- **修复**：显式 @MainActor 或 actor 封装。
- **来源**：WorkBuddy

### #21 dlopen 句柄管理
- **位置**：`App/components/Notch/NotchSkyLightWindow.swift:17-23`
- **问题**：每次 `undelegateWindow` 都 dlopen 且不 dlclose；handler 为 nil 时 `dlsym(nil,…)` 搜索全局符号表可能误命中。
- **修复**：dlopen 一次缓存为 static；nil 时直接返回。
- **来源**：WorkBuddy

### #22 Zip 临时文件清理缺失
- **位置**：`App/components/Shelf/Services/TemporaryFileStorageService.swift:224-229`
- **问题**：多文件 zip 失败路径 `return nil` 时拷贝副本未删除，临时目录累积垃圾；`createTempFile` 注释声称 "tracked for manual cleanup" 但实际无跟踪机制。
- **修复**：失败路径 defer 清理；实现真正的跟踪表。
- **来源**：WorkBuddy

### #23 IUO 崩溃隐患
- **位置**：`FloatingNestPanel.swift:687`、`ShelfItemView.swift:265`、`NestGroupCardView.swift:218`（`var item: ShelfItem!`）
- **问题**：AppKit 生命周期中先触达再赋值即崩溃。
- **修复**：改可选 + guard 或初始化注入。
- **来源**：WorkBuddy

## 六、测试与工程化

- **测试覆盖薄弱**：仅 3 文件 17 用例（音量钳制、sneak peek、摇晃手势、Shelf 分组）。持久化、XPC、剪贴板、书签解析、图片处理**零覆盖**——恰好是问题最集中的模块。建议优先补 #3/#5/#7/#8 的回归测试。（双方一致）

## 七、正面确认（不需要动的部分）

- 架构分层清晰（Service/ViewModel/View 分离），Manager 统一 `@MainActor` 单例
- `[weak self]` 使用规范，Timer / 全局 monitor / event tap / Carbon hotkey 均有成对释放
- XPC 全部 async 化，无同步阻塞；`remoteObjectProxyWithErrorHandler` 模式正确
- 电池走 IOKit RunLoopSource 事件驱动（无轮询）
- 单实例保护 `enforceSingleInstance()` 有效防双实例数据损坏
- XPC Helper 特权分离架构标准、安全
- ImageProcessingService 复用 CIContext；DragDetector 粘贴板读取有 changeCount 门控
- 锁屏时窗口清理（`onScreenLocked` → `cleanupWindows`）设计良好
