## 一、项目概况

DropNest 是 macOS 刘海区工具应用，派生自 [boring.notch](https://github.com/TheBoredTeam/boring.notch)，聚焦两项核心能力：

- **刘海媒体条（Now Playing）**：播放音乐时刘海展开，显示专辑封面与动态频谱。
- **文件暂存（Shelf）**：拖文件到刘海即可「钉」在面板，支持安全书签持久化与丰富的右键操作。

在 v1.0 中**新增了剪贴板历史管理模块**（详见下文），并完成了大量 UI/UX 打磨。

## 二、功能规划（需求分析阶段）

用户提出两类新功能需求，经讨论排定优先级：

| 功能 | 定位 | 参考实现 | 决策 |
| --- | --- | --- | --- |
| ① 悬浮暂存框 | 拖拽时在任意位置弹出可移动浮动窗口，临时收纳文件 | Yoink / Dropover / ShakePin | **暂缓**（未实现） |
| ② 剪贴板历史管理 | 复制后从历史直接取回，避免重复复制 | Maccy / Paste / Raycast | **先行（已上线 v1.0）** |

**底层设计思路**：两个功能可共享一套「内容表示层」（多类型载荷采集 → 过滤 → 存储），只是收集策略不同。本次先落地剪贴板历史，悬浮暂存框沿用已解耦的 `components/Shelf` 服务层，后续补窗口壳。

## 三、剪贴板历史功能 — 实现计划（Plan）

### 3.1 架构分层

```
采集层  ClipboardMonitor      500ms 轮询 NSPasteboard.changeCount，变化即抓取
  ↓
过滤层  ClipboardFilter       隐蔽类型跳过 / 来源 App 忽略 / 单条大小上限
  ↓
存储层  ClipboardHistoryStore 内存数组 + 内容哈希去重 + 容量/时效淘汰 + JSON/blob 持久化
  ↓
表现层  P1 刘海「剪贴板」页签（浏览/搜索/点选回拷）
        P2 快捷键光标处快速面板 + 自动粘贴 ⌘V
```

### 3.2 覆盖的内容类型

| 类型 | 剪贴板表示 | 处理方式 |
| --- | --- | --- |
| 纯文本 | `public.utf8-plain-text` | 最高频，全文保存 |
| 富文本 | `public.rtf` / `public.html` | 随文本一并保存，回贴原样写回 |
| 图片 | `public.png` / `public.tiff` | 二进制存 `blobs/`，JSON 仅存文件名 |
| 文件 | `public.file-url` | 仅存 URL 引用，不拷内容 |
| 链接 | `public.url` | 浏览器复制的 URL |

**关键决策**：
- 去重键 `contentHash`：同内容重复复制 → 置顶 + `copyCount+1`，不新增条目。
- 文件只存引用；图片二进制不入 JSON（与 Shelf 的 Bookmark 思路一致）。
- 隐私红线：跳过 `ConcealedType`/`TransientType` 及 1Password 等隐蔽类型，来源 App 可配置忽略。

### 3.3 实现清单（任务拆解与验收）

| # | 任务 | 产出 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 数据模型 + 去重哈希 | `ClipboardItem.swift` | 同内容复制两次只产一条且 `copyCount=2` |
| 2 | 采集器 + 隐私过滤 | `ClipboardMonitor` / `ClipboardFilter` | 文本/图片/文件均被捕获；1Password 不入库；自我回拷不重复 |
| 3 | 存储与淘汰 | `ClipboardHistoryStore` | 重启历史保留；超容量最旧条目连同 blob 清理 |
| 4 | 配置项 + 设置页 | `Constants.swift` / `SettingsView` | 容量、类型开关、忽略列表均可改且即时生效 |
| 5 | 刘海剪贴板页签 | `ClipboardHistoryView` 等 | 列表/搜索/点选回拷/失效置灰可用 |
| 6 | 快捷面板 + 自动粘贴 | `ClipboardQuickPanel` + 快捷键 | ⌃⌥V 光标处弹出；键盘可选；授权后自动粘贴 |
| 7 | 联调验收 | — | 通过全部边界场景 |

### 5.3 灵动岛状态监控能力补充（仅状态展示，不弹窗执行）

**背景**：boringNotch 整套「灵动岛」能力（折叠态刘海常驻显示实时信息）在裁剪 DropNest 时被删除。本次按用户要求**选择性补回**，遵循统一原则：

> **只做被动状态监控，不弹交互浮层、不执行动作**——与现有「媒体活动」一致：音乐播放时折叠态刘海被动显示专辑图 + 频谱，但**不弹出控制面板**去执行播放/暂停等动作。
> **对「弹出」的界定**：指 macOS 原生那种**居中模态浮层（bezel）**。若仅在刘海/菜单栏那一层做**内联状态变化**（条/百分比随按键短暂出现后淡出），不属「弹出执行」，可纳入。

**纳入范围（被动状态展示）**：

| 能力 | 折叠态/刘海层显示内容 | 数据来源 | 优先级 |
| --- | --- | --- | --- |
| 电池 / 充电指示 | 电量百分比 + 充电状态（充电动画可选） | `BatteryStatusViewModel` / IOKit | 高 |
| 日历下一事件 | 最近日程 chip（标题 + 时间） | EventKit | 中 |
| 系统 HUD 替换（刘海层内联变体） | 音量 / 亮度 / 键盘背光 的条 + 百分比，按键时在刘海层内联显示、短暂淡出 | `VolumeManager` / `BrightnessManager` + 事件拦截 | 高 |

- **HUD 具体项**：①**音量 Volume**（F10~F12 / 媒体键，最高频）②**亮度 Brightness**（F1/F2）③**键盘背光 Backlight**（F5/F6，仅带背光机型，优先级低）。

**排除范围（仍不符合原则）**：

- ❌ 镜像 / 摄像头、空闲脸动画、新手引导、提示系统、更新说明：非状态监控类，排除。
- ⏸ 音乐媒体活动：保持现状不动，作为参照范式。

**实现要点**：
- 复用 boringNotch 的 `components/Live activities` 思路，仅保留「状态展示」分支。
- 折叠态/刘海层显示接入现有 `NotchLayout` 折叠内容区，与 `MusicLiveActivity` 并列作为条件分支；HUD 走短暂 sneak peek（按键触发 → 内联显示 → 淡出），**不弹居中模态 bezel**。
- HUD 需拦截系统事件并隐藏原生 bezel（`MediaRemote` / `CoreGraphics` + 辅助功能权限），移植时评估沙盒与权限成本。
- 每个能力配独立功能开关（设置页可关），遵循已建立的「功能开关全链路生效」约定。

**验收标准**：
- 充电 / 低电时，折叠态刘海被动显示电量；无交互浮层。
- 有日程时，折叠态显示下一事件；不展开日历面板、不触发交互。
- 按音量 / 亮度键时，刘海层内联显示电平条 + 百分比并淡出；原生居中 bezel 被抑制，无模态弹窗。

## 六、构建与测试说明（环境备注）

> 本机构建环境存在沙盒限制：`xcodebuild` 的 SPM「Resolve Package Graph」会因沙盒失败，但**手动 `xcrun swiftc` 可完整构建出可运行 App**。

**手动构建路径**（供参考）：
1. 将全部 app 源码（剥离 `#Preview` 块）与已编译的包 `.o`（DerivedData 中的 `Defaults`/`LaunchAtLogin`/`SkyLightWindow`）、`swift-syntax` 预编译 `libMacroSupport.a` 用 `xcrun swiftc` 链接为单一可执行文件。
2. 塞入 `DropNest.app/Contents/MacOS/`，加 `-Xlinker -rpath -Xlinker @executable_path/../Frameworks`。
3. `codesign --force --deep --sign -` 重签后 `open` 启动。

**功能验证**：
```bash
echo "测试文本" | pbcopy
# 检查持久化文件是否出现该文本：
cat ~/Library/Application\ Support/boringNotch/ClipboardHistory/items.json
# 重复复制同一内容 → copyCount 应 +1（验证去重置顶）
```
