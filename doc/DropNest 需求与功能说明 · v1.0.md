## 目录

## 一、产品定位 🎯

**一句话定位**：把 MacBook 的刘海变成你的「第二桌面」。

**完整定位**：DropNest 是一款 macOS 刘海区工具应用，closed 态为媒体信息监听条 + 系统 HUD 指示器，open 态为文件暂存架 + 剪贴板历史管理器。通过悬浮暂存巢群，DropNest 把「暂存」从刘海延伸到整个桌面，实现「随处可存、自动留存、成组规整、双向流转」的工作流。

**核心架构思想**：

- **万物皆入巢**：文件拖放、剪贴板复制、链接收藏，统一为 `ShelfItem` 数据模型，由 `ShelfStateViewModel` 单例管理
- **刘海 ⇄ 桌面双向流转**：集合（group）既可以聚合在刘海 Shelf 内，也可以独立展开为桌面悬浮巢，数据始终单一来源
- **零高危权限**：不申请「完全磁盘访问」，文件访问走 security-scoped bookmark；系统 HUD 走辅助功能权限（运行时按需授予）

**与原版 boring.notch 的范围差异**：

| 模块 | boring.notch | DropNest v1.0 |
|------|--------------|---------------|
| 刘海媒体条 | ✅ | ✅ 保留并优化 |
| 文件暂存 Shelf | ✅ 基础拖放 | ✅ 扩展为集合 + 右键操作 + 图片处理 |
| 悬浮暂存巢群 | ❌ | ✅ 全新模块（差异化核心） |
| 剪贴板历史 | ❌ | ✅ 全新模块 |
| 系统 HUD 替换 | ❌ | ✅ 全新模块（音量/亮度/键盘背光） |
| 电池指示 | ❌ | ✅ 全新模块 |
| XPC Helper 架构 | ❌ | ✅ 全新模块（特权能力分离） |

## 三、R1 刘海媒体条（Now Playing）🎵

### 3.1 用户场景

播放 Apple Music / Spotify / 网页播放器时，刘海自动展开显示专辑封面、曲目信息与动态频谱；暂停后自动收起为细条，不遮挡屏幕内容。

| 编号 | 功能点 | 说明 | 优先级 |
| --- | --- | --- | --- |
| FR-M1 | 媒体状态获取 | 通过 mediaremote-adapter 子进程对接系统级 Now Playing 接口，支持任意播放器 | P0 |
| FR-M2 | 专辑封面展示 | 刘海两侧展开显示当前曲目专辑封面 | P0 |
| FR-M3 | 动态频谱 | 播放时显示动态音频频谱可视化 | P1 |
| FR-M4 | 自动收起 | 暂停后自动收起为细条，不遮挡屏幕 | P0 |
| FR-M5 | 智能标签页切换 | 根据最近活动（文件暂存 / 剪贴板复制）自动切换默认标签页 | P1 |

### 3.3 验收标准

- [x] 支持 Apple Music、Spotify、网页播放器等任意播放器
- [x] 播放时刘海展开显示封面与曲目信息

- [x] 全流程无新增系统权限

## 五、R3 悬浮暂存巢群（Floating Nest）🪺

### 5.1 用户场景

拖着文件出发 → 桌面上已有的暂存巢进入可接收高亮态、鼠标附近同时出现一个浅色「空巢胚」→ 拖进既有巢 = 加入那个集合；拖进空巢胚 = 孵化出一个新集合；都没用上 → 空巢胚静默消失。「仅摇晃召唤」模式下，晃一晃鼠标手动唤出空巢胚。

### 5.2 功能点清单

| 编号 | 功能点 | 说明 | 优先级 |
| --- | --- | --- | --- |
| FR-F1 | 空巢胚落点 | 拖拽文件时鼠标附近自动浮现紧凑胶囊式落点指示器，松手即孵化为正式巢 | P0 |
| FR-F2 | 摇晃召唤 | 拖拽过程中横向摇晃鼠标，指针附近瞬间召唤空巢胚；纯指针驱动，无需键盘快捷键 | P0 |
| FR-F3 | 悬浮巢窗口 | NSPanel（non-activating + floating），每个巢 = 一个集合（groupID） | P0 |
| FR-F4 | 共享数据源 | 与刘海 Shelf 共用 ShelfStateViewModel 单例，双边实时同步 | P0 |
| FR-F5 | 生命周期 | 空巢胚：拖拽结束未使用即销毁；正式巢：可收起回刘海、位置按组记忆 | P0 |
| FR-F6 | 触发方式 | 设置项二选一：拖拽开始自动显示巢群（默认）/ 仅摇晃召唤；灵敏度可调 | P0 |
| FR-F7 | 多巢并存 | 桌面可同时存在多个巢；拖拽期间已有巢进入可接收高亮态 | P0 |
| FR-F8 | 网格自适应 | n×n 正方形网格（2~4 个 → 2×2；上限默认 3×3、设置项可调）；超出纵向滚动；窗口随网格自适应尺寸 | P0 |
| FR-F9 | 三层手势分离 | 拖标题栏 → 移动窗口；拖空白区 → 整体拖出全部文件；拖单个条目 → 只拖出该文件 | P0 |
| FR-F10 | 一键流转 | 全部集合一键展开为桌面巢群，或一键收回刘海 | P0 |
| FR-F11 | 位置记忆 | 巢位置按 groupID 记忆并还原 | P0 |

### 5.3 验收标准

- [x] 拖拽开始后 300ms 内：已有巢进入可接收高亮态；若无空巢胚则鼠标附近出现浅色空巢胚
- [x] 拖入空巢胚 → 孵化为正式巢并成为新集合；拖入既有巢 → 加入该巢集合
- [x] 拖拽结束未使用空巢胚 → 空巢胚自动消失，不留痕迹
- [x] 巢网格按内容数自适应（2~4 个 → 2×2；5~9 个 → 3×3；超出纵向滚动）
- [x] 拖入巢的文件立即出现在刘海 Shelf（双向同步）
- [x] 巢不夺取焦点（当前 App 保持激活）
- [x] 三层手势分离正常工作
- [x] 全流程无新增系统权限

## 十、R8 XPC Helper 架构 🔧

### 10.1 设计依据

主 App 保持沙盒化以符合 Mac App Store 规范，但屏幕亮度、键盘背光等需要私有 API 的能力无法在沙盒内调用。通过独立 XPC Helper（非沙盒）调用这些特权能力，实现「沙盒合规 + 特权能力」的兼容。

### 10.2 功能点清单

| 编号 | 功能点 | 说明 | 优先级 |
| --- | --- | --- | --- |
| FR-X1 | 屏幕亮度调节 | DisplayServices + IOKit 私有 API | P0 |
| FR-X2 | 键盘背光调节 | CoreBrightness 私有框架（动态加载 KeyboardBrightnessClient） | P0 |
| FR-X3 | 辅助功能授权 | XPC 侧检查并请求辅助功能权限 | P0 |

## 十一、统一数据模型 🧬

<aside>
🧬

**ShelfItem**：id（UUID）· kind（.file(bookmark) / .text(string) / .link(url)）· isTemporary（Bool）· groupID（UUID?，nil = 独立条目）
**数据源**：DragDetector（拖拽）+ ClipboardMonitor（changeCount 轮询）
**存储**：ShelfPersistenceService（书签持久化，800ms 防抖 + 后台写盘）
**缓存**：ShelfItemResolutionCache（书签解析/展示名/图标缓存，30s TTL + NSLock 保护）
**出口**：刘海 ShelfView / FloatingNestPanel（共享渲染，悬浮巢按 groupID 过滤）
